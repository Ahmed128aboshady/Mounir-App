# أكاديمية منير — Mounir App

واجهة عربية RTL للطالب والمعلم والإشراف، بثيم فاتح وتصميم مناسب للموبايل. تعرض البيانات الحالية من Supabase بعد تسجيل الدخول؛ لا تتضمن بيانات طلاب أو حسابات تجريبية أو قاعدة بيانات منسوخة.

## الربط بالاستضافة

هذا تطبيق Python يحتاج خادمًا. **GitHub Pages والاستضافة الثابتة وحدهما لا يشغلانه.** يمكن للاستضافة تشغيل Dockerfile الموجود، أو تشغيل Python 3.12 مع الأوامر التالية:

```sh
pip install -r requirements.txt
python local_live/local_live_server.py
```

أضف المتغيرات التالية من لوحة الاستضافة، ولا تكتب القيم الفعلية في GitHub:

| المتغير | القيمة المطلوبة |
|---|---|
| `SUPABASE_URL` | رابط مشروع Supabase الحالي للأكاديمية |
| `SUPABASE_ANON_KEY` | مفتاح الاتصال العام الحالي؛ يبقى في الخادم ولا يقدم للمتصفح |
| `APP_ENV` | `production` |
| `PUBLIC_ORIGIN` | رابط الاستضافة النهائي بـ HTTPS، بدون مسار أو شرطة أخيرة |
| `PORT` | منفذ الاستضافة؛ الافتراضي `8010` |
| `DATA_DIR` | مسار تخزين دائم لسجل العمليات؛ في Docker استخدم `/app/.runtime` |

الاستضافة يجب أن توفر HTTPS وتوجه الطلبات إلى المنفذ المحدد وتحافظ على اسم المضيف العام في `Host`. شغّل **نسخة واحدة فقط** من الخدمة؛ الجلسات والقفل في ذاكرة العملية. يجب توفير تخزين دائم لـ `DATA_DIR` وعدم حذف سجل العمليات عند إعادة النشر. إعادة تشغيل الخادم تستلزم تسجيل الدخول من جديد.

بعد الربط افتح:

- `/login.html` للطلاب والمعلمين.
- `/admin-login.html` للإشراف. يقبل اسم `admin` كبديل للحساب الحالي `Mounir`، مع التحقق من كلمة المرور الحالية.
- `/api/health` لفحص تشغيل الخدمة.

لا يوجد تجاوز لكلمة المرور أو تسجيل دخول تلقائي. عند غياب إعدادات الاتصال أو عنوان HTTPS الصحيح يرفض الخادم بدء وضع الاستضافة.

## التشغيل المحلي

عيّن `SUPABASE_URL` و`SUPABASE_ANON_KEY` في بيئة التشغيل، واجعل `APP_ENV=development`، ثم شغّل الأمر نفسه وافتح `http://127.0.0.1:8010/login.html`. ملف `.env.example` دليل للمتغيرات؛ التطبيق لا يقرأ ملفات `.env` تلقائياً. يمكن تمريرها عبر لوحة الاستضافة أو `docker run --env-file`.

## ما يشمله

الطالب: الحصة، الجدول، الرصيد والحضور، خطة الحفظ، المحتوى والاختبارات والنتائج، طلب التجديد وكشف الحساب والدعم.

المعلم: الحصص والمجموعات والمواعيد، الرصد ومراجعة إلغائه، الدعم والمستحقات.

الإشراف: البحث في الطلاب وملفاتهم، الحالة والخطط والشحن، المجموعات ونقل الطلاب وتعديل المواعيد، الحضور، التذاكر، المعلمون، المالية، المحتوى والاختبارات والتقارير وسجل العمليات.

## البيانات والحدود التشغيلية

**أي حفظ بعد الاتصال يؤثر في بيانات الأكاديمية الحقيقية.** لا ينفّذ التطبيق seed أو إنشاء حسابات أو تعديل مخطط Supabase عند التشغيل.

- سياسات قاعدة البيانات الحالية وطريقة حفظ كلمات المرور لم تتغير. هذه نسخة مراجعة وظيفية؛ ليست تدقيقاً أمنياً شاملاً للنظام القديم. راجع سياسات RLS والحسابات قبل تعميم الاستخدام.
- عمليات الجداول المتعددة ليست معاملات سحابية ذرية. يستخدم الخادم فحص الحالة وسجلاً دائماً لمنع تكرار الطلب نفسه. رسالة التنفيذ الجزئي تستلزم مراجعة السجلات قبل إعادة العملية. تطبيقات الأكاديمية الأخرى لا تشارك القفل المحلي.
- بعض النوافذ القديمة في بوابة المعلم ما زالت تستخدم وظائف الواجهة الأصلية. العمليات غير المرتبطة ترجع خطأ صريحاً، ولا تحفظ في قاعدة بديلة.
- ملاحظات مطابقة الإشراف على الجهاز؛ الحضور الرسمي في السحابة. تصدير البيانات للمراجعة يستبعد كلمات المرور. الاستعادة وإدارة حسابات الدخول غير مفعّلتين هنا.
- التجديد يرسل طلباً ولا يحصّل أموالاً إلكترونياً. التسوية تسجل دفعة تم دفعها؛ لا تنفذ تحويلاً. المستحقات مبنية على معادلة المنصة الحالية للمحاضرات المكتملة، وتحتاج مراجعة الحسابات.
- لا تُعرض نسبة إنجاز أو شهادة مختلقة. مدة الاختبار مسجلة وليست مراقبة زمنية محكمة للامتحان.
- ملفات الخطوط والأيقونات وTailwind في الواجهة الأصلية تعتمد على خدمات CDN، وتحتاج اتصالاً بالإنترنت.

## الاختبارات

```sh
python -m unittest discover -s tests -v
```

تستبدل الاختبارات اتصال السحابة ببيانات في الذاكرة، ولا تستخدم حسابات حقيقية. تمت مراجعة التنقل للأدوار الثلاثة، ومراجعة بصرية للدخول ونوافذ الإشراف على عروض 320 و390 و430 و768 بكسل.
